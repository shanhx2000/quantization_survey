Abstract
Neural Scene Representation (NSR) is a promising technique for
representing real scenes. By learning from dozens of 2D photos
captured from different viewpoints, NSR computes the 3D representation of real scenes. However, the performance of NSR processing running on GPU is insufficient for applications. Cambricon-R
achieves high performance of more than 60 scenes per second, but
at the cost of modeling quality.

Introduction

Neural scene representation (NSR) is a novel algorithm to reconstruct 3D representation of real scenes. It learns the encoded 3D
representation from dozens of 2D photos taken from RGB cameras. The 3D information can then be used for novel view rendering [25, 27, 29], scene editing [2, 17, 53], relighting [43, 47, 54], and
so on. Compared to traditional 3D reconstruct technique, it avoids
the substantial human efforts and expensive laser cameras required
for 3D representation, significantly reducing the cost and time for
realistic 3D representation.
NSR can be applied to various fields such as autonomous driving [6, 15, 51, 52], embodied intelligence [1, 5, 7, 18, 30, 56], and
AR/VR [10, 23]. However, the insufficient modeling performance
of NSR limits its application. In many real-world applications, the
surrounding environment is changing, requiring continuous NSR
modeling of the environment. For instance, in autonomous driving,
modeling the environment requires low latency. Due to the insufficient modeling performance of NSR, current NSR can only model
environmental information offline for data generation and driving
simulation, and cannot be used for modeling the environment online [6, 15, 48, 51]. Similarly, in embodied intelligence, using NSR for
scene reconstruction can help robots understand and interact with
the scene [5, 7, 30]. However, the NSR modeling process in these
applications is often completed offline in advance [1, 18, 56], thus
only supporting pre-determined static scenes. These applications
set high demands on both the performance and quality of NSR.
However, the performance of NSR running on GPUs is insufficient. For example, it takes at least 5 seconds to compute the representation of a scene on A100 [36], which cannot meet the requirement of the aforementioned applications. Several accelerator architectures have been proposed to speed up NSR processing [24, 42, 55].
Accelerators like Instant-3D [24] and Instant-NeRF [55] are designed for edge devices. They improve the NSR performance by
around 200 times compared with edge-end GPUs and achieve NSR
performance of around 1 scene per second. Other accelerators like
Cambricon-R [42] are implemented on a large chip. By keeping the
encoding table on chip, almost all off-chip memory accesses are
eliminated. They achieve NSR performance of more than 60 scenes
per second. However, the high performance of Cambricon-R is

In this paper, we aim to improve both the performance and quality of NSR accelerator with a key technology of sparse encoding
table. We observe that a large number of the entries in the encoding
table can be pruned with negligible impact to the representation
quality of NSR, as shown in Figure 4. When using the sparse encoding table, memory accesses to the pruned entries can be avoided
to speed up the encoding stage, which is bottleneck stage of NSR
due to the heavy fine-grained irregular memory accesses even for
on-chip memory [42].
Based on this observation, we first propose a training algorithm
called sparse table NSR (ST-NSR), which achieves more than 80%
sparsity of the table during the forward stage and more than 90%
sparsity of the table gradient during the backward stage at the cost
of negligible accuracy loss. To the best of our knowledge, this is
the first NSR training algorithm with sparse encoding tables. We
observe that as the size of the encoding table increases, the sparsity
rate grows, resulting in a reduction of required memory accesses,
as shown in Figure 3. However, a larger encoding table comes at
the cost of an increased memory footprint, making it impossible to
store the entire table on-chip. Based on the design space exploration
of different table sizes, we determine that a table size of 128 MB
maximizes the number of invalid memory access requests while
ensuring that the sparse table can still be stored on-chip.

In the update stage of ST-NSR, a dense table must be maintained
to accumulate gradients. Due to the large size of the dense table,
it must be stored off-chip. As a result, the large amount of offchip memory access to this table in the update stage becomes a
performance bottleneck. To address this challenge, we propose
sparse update unit that efficiently updates the sparse table on-chip
with sparse storage format, thus avoiding off-chip memory access
to the dense table and reducing the memory access volume by 83.5%
compared to the straightforward approach.
Efficient memory access to the on-chip sparse table is challenging.
During the forward stage, many invalid memory requests occur for
pruned entries. Efficiently eliminating these requests before accessing the sparse table is difficult due to the irregular access patterns of
the sparse structure bitmap. We propose a Sparse Index Unit (SIU)
based on sequential SRAM accessing and parallel address matching
to address this challenge. With an additional area overhead of 8.59%,
SIU achieves high throughput filtering of memory access requests,
thereby increasing the throughput of encoding stage by 7.54×.
After improving the throughput of the encoding stage, the MLP
stage becomes a new bottleneck of ST-NSR algorithm. However,
due to the large local buffer used by each MLP unit, increasing the
MLP units by 4× would require an additional total buffer capacity
of 144 MB, significantly raising the cost of the chip. We propose
a design with dynamic shared buffers that reduces the average
buffer capacity required per MLP unit by 85.3%. As a result, we can
increase the number of MLP units by 4× to improve performance
with acceptable size of buffer requirement.
We conduct experimental evaluations on 8 typical scenes. The
results show that, compared with A100 GPU and the state-of-theart NSR training accelerator Cambricon-R, Cambricon-SR achieves
1259× and 4.12× speedup, and reduces the energy consumption by
1139× and 2.98× for each training iteration of NSR, respectively.
Thus, we improve both the performance and quality of NSR. As
shown in Figure 1, under the same modeling speed, the quality
improvement comes from more iterations of training.
The contributions of this paper are summarized below:
• We propose the first NSR algorithm with sparse encoding
table (ST-NSR). It achieves more than 80% sparsity of the
encoding table and its gradients. We implement ST-NSR on
GPU and it achieves a 1.55× speedup in the encoding stage
and a 1.19× overall speedup.
• We propose the Sparse Update Unit to reduce 83.5% of the
off-chip memory accesses in the update stage. It decreases
the execution time for the update stage by 5.28×.
• We propose the Sparse Index Unit (SIU) based on sequential
SRAM access to address the challenge of irregular memory
access to the bitmap. It achieves a throughput increase of
7.54× during the encoding stage with an additional area
overhead of 8.59%.
• We propose the dynamic shared buffer for the MLP units to
reduce the buffer usage by 85.3% so that we can increase the
number of the MLP units by 4× with acceptable capacity of
on-chip buffers.
• We conduct thorough experimental evaluation of CambriconSR. The results show that, compared with A100 GPU and
the state-of-the-art NSR training accelerator Cambricon-R,

2 Background and motivation
2.1 NSR Algorithms
NSR algorithms are primarily divided into two main categories:
NeRF-based [33] and 3DGS-based [19]. In this paper, we focus
on NeRF-based NSR algorithms. 3DGS-based algorithms explicitly
represent the scene using millions of discrete Gaussians in 3D space.
In contrast, NeRF-based algorithms learn implicit representation of
a scene by sampling points in 3D space and using MLPs to learn
the mapping between spatial position of points and their color and
volume density. However, due to the large size of the MLP, the
modeling speed is exceedingly slow, making it difficult to meet the
demands of applications.
To improve modeling efficiency, optimized NSR algorithms combine encoding table with small MLPs. Each point is obtained through
a lookup table to get encoded features, which are then processed
by small MLPs. This method significantly reduces the computational workload for each point. Currently, many mainstream NSR
algorithms [4, 9, 12, 36, 46, 49] adopt this technique of combining encoding table with small MLPs. A training iteration of the
algorithms consists of following stages, as illustrased in Figure 2:
(1) Sampling. In the sampling stage, pixels are randomly sampled from the training images. The coordinates and the RGB color
of sampled pixels are the input and the ground truth of the NSR
process, respectively. To compute the color of pixels, each pixel is
mapped to a ray [33, 36] or a cone [3, 4], which starts from the camera viewpoint through the corresponding pixel along the viewing
direction. Then, points are randomly sampled along each ray or
cone. The coordinates (𝑥, 𝑦, 𝑧) and view direction (𝜃, 𝜙) of these
sampled points are computed and transmitted to the next stage.
(2) Encoding. Hash grid [36] and Multi-planes [12] are two
mainstream encoding methods of NSR. The process of hash grid

In multi-planes encoding [12], sampled points are first projected
to multiple planes (x-y plane, x-z plane, and y-z plane in case of
3D space). Each plane corresponds to a series of encoding tables
at different levels of resolution. Similar with hash grid, the feature
vector of a point is computed through bilinear interpolation of 4
vertices of the grid that surrounds the point at each level. Then,
features of different planes from the same level are reduced using
operations such as element-wise multiplication.
(3) MLP. In the MLP stage, the encoded feature vector of each
sampled point is fed into MLPs to predict the RGB color and volume
density of the point.
(4) Volume Rendering & Loss Computing. Volume rendering
is performed to accumulate the colors and densities of sampled
points along each ray, resulting in the color of the corresponding
pixel. Then, the computed pixel color is compared with the ground
truth color to calculate the loss.
(5) Parameters Updating. After computing the loss, gradients
are back-propagated through the above pipeline. The learnable
parameters in NSR, primarily including entries in encoding tables
and weights of MLPs, are optimized using optimization algorithm
such as gradient descent.

2.2

NSR Accelerators

Some applications of NSR algorithm, such as autonomous driving
and embodied intelligence, require a high 3D representation performance. However, executing NSR processing for a typical scene takes
at least 5 seconds on A100 to achieve an acceptable representation
quality, which cannot meet the requirement of these applications.
Some researchers have proposed designs for NSR accelerators to
address the performance gap.
Instant-NeRF. Instant-NeRF [55] accelerates NSR training using a Near Memory Processing (NMP) architecture. To address the
memory access bottleneck in the NSR processing, Instant-NeRF integrates computing units directly on the memory, achieving greater
bandwidth.
Instant-3D. Instant-3D [24] splits the hash grid into two branches
and reduces the grid size and update frequency for the less sensitive
branch. It also minimizes memory read/write operations during
hash grid interpolation by employing memory access merging.
NeuGPU. NeuGPU [40] is an NSR training accelerator chip that
has taped out. It partitions the encoding table for better spatial

1257

locality, and skips the access of encoding table when the sampled
point is far from the grid veritces.
These three accelerators are designed for edge devices and achieve
huge improvement against edge-end GPUs. However, due to the
limited hardware resources of edge-end chips, high performance
NSR processing cannot be achieved by these accelerators.
Cambricon-R. Cambricon-R [42] introduces a fully fused architecture to address the memory access challenges in NSR. It proposes
a ray-based execution flow which keeps almost all data on-chip,
thereby eliminating the majority of off-chip memory accesses. Additionally, it introduces an network-on-chip (NoC) to alleviate the
fine-grained irregular memory access conflicts during encoding
table access, thus resolving the memory access challenges during
the encoding stage. As a result, Cambricon-R achieves high performance NSR processing for the first time with on-chip storage
resources comparable to those of an A100.
However, Cambricon-R has insufficient training iterations under
high performance requirements. The NoC for accessing encoding
table has limited throughput. When improving the throughput
of the NoC, the additional area cost of wires and buffers will increase rapidly as the number of banks increases. Due to insufficient
throughput, Cambricon-R can only complete 250 training iterations for each scene, which seriously damages the modeling quality,
especially for large-scale scenes.

3

ST-NSR Algorithm

Multiple works [21, 24, 42, 55] have demonstrate that a large number
of irregular table accesses during the encoding stage are a performance bottleneck of NSR process. In order to reduce the number
of encoding table access, we adopt a sparse algorithm ST-NSR to
prune the encoding table and its gradients during training.

gradients must be continuously accumulated for all entries until
their accumulated values exceed or fall below a threshold, triggering
changes in sparsity. However, since ST only contains the active
entries that have not been pruned in the current iteration, it cannot
fulfill this requirement. Therefore, it is necessary to maintain a
DT that includes all entries to accumulate gradients. This ensures
that pruned parameters still have a chance to be restored rather

3.2

Sparsity-Size Trade-off

We observe that the size of the dense table (DT) has a significant
impact on sparsity rates. We evaluate the sparsity rates under different table sizes, ensuring that the PSNR degradation does not
exceed 0.5. The experimental results are shown in Figure 3. As
the size of DT increases, higher sparsity rates are achieved. Since
the total volume of accesses to the tables is same across different
DT sizes, the volume of valid accesses is reduced, thereby creating
potentials for performance improvement. However, the increase in
the size of DT also results in a larger ST. To reduce the volume of
valid accesses by increasing the DT size while ensuring that the ST
can be stored on-chip, we select the DT size to 128 MB. Under this
configuration, the size of the sparse table is no more than 26 MB.
And according to our evaluations, the size of table gradients is no
more than 14 MB in this case, meaning that sparse table and table
gradients can be stored in a 40 MB on-chip buffer.

encoded features in the backward stage. Under the aforementioned

of sparsity in the forward stage on the modeling quality (measured
in PSNR), while the sparsity in the backward stage is set to 0. The
results indicate that when the sparsity rates for 8 typical scenes are
set to 86%, 88%, 96%, 94%, 82%, 80%, 84%, and 82%, respectively, the

According to our evaluation of Instant-NGP [37], a representative NSR algorithm, the encoding stage is most time-consuming,

encoding stage. In this section, we implement ST-NSR algorithm on

We first attempt to leverage the structured sparsity hardware of the A100 to support ST-NSR, but find it to be completely ineffective. The structured sparsity in the A100’s Tensor
Cores, such as 2:4 sparsity, is designed to accelerate matrix multiplications in NNs by reducing MAC operation overhead [34]. In
contrast, ST-NSR leverages sparsity to reduce memory access in the
encoding stage, which does not involve any matrix multiplication
operations, making structured sparsity hardware ineffective for STNSR. Moreover, applying the structured sparsity algorithm to
sparse encoding table is also ineffective. We apply structured
sparsity to the encoding table with the same sparsity rate as ST-NSR.
Experiments show that it not only fails to improve performance
but also degrades quality, reducing PSNR by 1.5 dB. This is because
structured sparsity (e.g., 2:4) requires accessing four consecutive
entries as a group to gain performance benefits. However, accesses
to the encoding table are irregular single-entry lookups, resulting in
no performance gain. Moreover, the fixed sparsity pattern further
degrades modeling quality.
In our GPU implementation of ST-NSR, sparse table (ST) is kept
resident in the L2 cache to reduce off-chip memory accesses, as its
size is less than 40 MB. To further filter out invalid ST accesses, a
bitmap stored in shared memory is utilized to track the sparsity
state of each table entry. Since each block in our CUDA kernel
only processes one level of encoding table, we only load the bitmap
corresponding to that level into shared memory. However, shared
memory on A100 (164 KB per block) cannot accommodate the complete bitmap of one level (256 KB). To address this issue, we employ
a hash table, which saves storage to 128 KB through hash mapping
at the cost of hash collisions that may cause a small number of
pruned entries to be misidentified as valid.

Cambricon-SR

In this section, we present Cambricon-SR, a hardware architecture

4.1

Overall Dataflow of Cambricon-SR

points.

4.2

Overall Architecture of Cambricon-SR

The overall architecture of Cambricon-SR is optimized for the STNSR algorithm based on a fully fused on-chip processing architecture, as illustrated in Figure 8.
In Cambricon-SR, the Global Buffer primarily stores the training data for each training iteration, the weights of the MLP, and
the accumulated gradients of the MLP. The Sampling Module
is responsible for performing the conversion from pixels to rays,
as well as sampling points along the rays. The MLP Module handles the training of the MLP. The MLP module comprises 512 MLP
units, each consisting of two 32 × 32 MAC (Multiply Accumulate)
arrays. The optimized design of the MLP Module will be discussed
in Section 4.5. To enable sparsity in the backward stage of the STNSR algorithm, the MLP unit includes a Point Gradients Sparse
Unit (PGS Unit), which is designed to prune the gradients of the
encoded features obtained during the backpropagation of MLP.
The Update Module gathers and accumulates the weight gradients from the MLP module, then updates the weights in the global
buffer. Based on the architecture of [8], which is constructed with

1260

a bitonic sorter and cascaded bidirectional insertion sorting units,
the Update Module performs top-k sorting on DT and updates
the sparsity threshold.
Encoding Module. The Encoding Module is responsible for
performing memory access to the sparse tables and executing the
interpolation for each sampled point. Inside the encoding module,
the Pre-process Unit is responsible for calculating the addresses
of the vertices surrounding the sampled points in the table at each
level. The Sparse Index Unit (SIU) is responsible for eliminating
invalid memory access requests for entries that have been sparsified.
Details of SIU will be discussed in Section 4.4.
Sparse Table Array (STA). The encoding module is composed
of 16 STAs, corresponding to 16 levels of encoding tables,with a
total of 40 MB SRAM. The STA performs high-throughput memory
access to the the sparse table and its gradients. STA is implemented
based on the Auto-Interpolation Bank Array of Cambricon-R [42]
since it achieves SOTA throughput of encoding in NSR. Specifically,
nodes in the array are interconnected in a mesh NoC. Each node
contains an SRAM bank that stores a part of sparse tables and
gradients. During the encoding process, memory access requests
are transmitted between nodes via the NoC. And data access and
interpolation computations are performed when the request arrives
at the corresponding node. This approach resolves bank conflict
issues through asynchronous control of different nodes. Compared
to Cambricon-R, we modify the structure of node to efficiently
support ST-NSR algorithm. As shown in Figure 8, CAM and Sparse
Update Unit (detailed in Section 4.3) are integrated into the STA.
Content Addressable Memory (CAM). To improve space utilization of the STA, we compactly store the valid entries of the
sparse table in SRAM. However, each access to an entry in the
sparse table (ST) requires the translation of the original address
in the dense table (DT) to the address in the sparse table, to correctly access the entry from the on-chip SRAM. We propose the
use of CAM to implement this address translation. CAM is a type
of memory device that, upon inputting its stored content, returns
the corresponding address of the content. Each node in STA has a
corresponding CAM to perform address translation. As shown in
Figure 9 (left), the entry at DT address 3 is accessed, translated to
the corresponding ST address 1 via the CAM, and then the entry
13 at SRAM address 1 is retrieved.
In our hardware configuration, each node in the STA can store
up to approximately 2,500 table entries and table gradients in total. To reduce the significant area and energy overhead associated
with the parallel match of such a large number of entries in the
CAM, we adopt a blocking strategy, a technique commonly used
in the design of large CAM [41]. Specifically, each node includes
16 blocks of CAM, each with 160 entries. Each block operates independently, handling search, read, and write operations. When a
request with an address from the dense tables arrives at the CAMs.
The corresponding block of CAMs is determined by the upper 4
bits of the address, and only the selected block is activated. We evaluate the CAM design using Synopsys Design Compiler. According
to our experimental results, the total area of the 15 MB CAM in
Cambricon-SR is 33.56𝑚𝑚 2 , accounting for 14.29% of the total chip
area.

4.3

Sparse Update Unit

According to our evaluation, off-chip memory access to the DT
accounts for 72.1% of the total ST-NSR processing time, making it a
significant performance bottleneck. In the ST-NSR process, there
are two stages that require accessing the off-chip DT. Firstly, during
the update of the DT, we observe that the table gradients exhibit a
sparsity of at least 89%, meaning that no more than 11% of the DT
data needs to be loaded and stored even once. This stage contributes
to 13.0% of the total ST-NSR processing time. Secondly, during the
update of ST, all entries in the DT are read to update the on-chip ST.
Even though DT access is regular and continuous, the large volume
of data results in this stage accounting for 59.1% of the processing
time.
To alleviate the performance degradation caused by the large
volume of off-chip memory accesses, we propose a sparse update
strategy to optimize the update process for ST. By comparing the
encoding tables of adjacent iterations, we observe that the sparsity
of entries tends to stabilize as the training progresses. After each
iteration, sparsity of only no more than 0.8% of entries changes,
except for the first 20 iterations. This insight inspires us to update
the ST incrementally.
However, when updating the ST, some new entries, whose absolute values after updating exceed the sparsity threshold, need to
be inserted into the ST. Similarly, some entries whose values fall
below the sparsity threshold need to be deleted from the ST. This
process is challenging because the on-chip ST is stored compactly.
The straightforward implementation involves first identifying the
entries to be deleted, shifting all subsequent entries in the compact
storage to fill the gap created by the deletion, and then finding
the appropriate position for the new entries to be inserted. This
requires a significant amount of data movement in the storage of
the ST, leading to severe performance degradation.
To address this issue, we design a sparse update unit based on outof-order storage and in-place data replacement, as shown in Figure 9.
During the update of DT, Cambricon-SR computes the new value of
changed entries. Then, it compares the values before and after the
update with the sparsity threshold to classify changed entries into
4 categories according to the sparsity state of each changed entry.
For entries changing from sparse to sparse, Cambricon-SR skips

1261

them as no on-chip updating of ST is required. For entries changing
from dense to dense, as these entries are already stored on-chip,
Cambricon-SR directly write the updated value into ST ("21" and
"15" in Figure 9). This process is performed simultaneously with
the update of the DT. For entries changing from sparse to dense,
the address in DT and the updated value are stored into Queue A in
the Sparse Update Unit. For entries changing from dense to sparse,
the address in DT is stored into Queue B in the entry update.
In each STA node, one data is read from each of the two queues
simultaneously. From Queue A, an address (Address A, "1" in Figure 9) and an entry (Entry A, "6" in Figure 9) are read. From Queue
B, an address (Address B, "5" in Figure 9) is read. First, Address B
is translated into the corresponding address in ST (Address C, "2"
in Figure 9) through CAM. Then, the Address A is write into the
Address C of the CAM and the Entry A is write into the Address C
of the SRAM bank for sparse entries. This mechanism ensures that
the space released by an old entry (stored at address B in the node)
is directly utilized to store the new entry, and the address data in
CAM is updated accordingly.
Since the sparsity threshold is updated based on the predetermined sparsity rate, the number of entries in the two queues is
roughly equal. For minimal extra entries (around 0.03%), if the entry is in Queue B, it is removed from the CAM and SRAM, and the
last entry is moved to its position. If the entry is in Queue A, it is
added to the end of the CAM and SRAM. Note that the capacity of
the CAM and SRAM in Cambricon-SR is redundant to accommodate
such minimal extra entries. As a result, Cambricon-SR avoids the
overhead of extensive data movement, achieving efficient update
of ST.
Through the aforementioned optimizations of sparse table update, Cambricon-SR reduces the total memory accesses during the
table update process by 6.06×. The overall execution time for the
update stage has decreased by 5.28×, and the proportion of time
spent on the update stage to the total time has decreased to 32.85%.

4.4

Sparse Index Unit

The ST-NSR algorithm significantly reduces the number of valid
table entries that need to be stored. However, due to the hash function in the encoding stage, the mapping between grid vertices and
table entry addresses is irregular, making it difficult to determine
which entries are pruned during memory access request generation. Due to the high sparsity of encoding tables, a large portion of
memory access requests target invalid addresses, leading to wasted
bandwidth in the sparse table array and severe congestion in the
NoC. To improve memory access throughput in ST-NSR, invalid
memory access requests must be identified and eliminated before
reaching the sparse table array. We introduce the sparse index unit
(SIU) to efficiently handle this problem.
4.4.1 Challenges. The throughput requirement of SIU is estimated
according to the typical sparsity of around 86% and the throughput
of the sparse table array of 256 requests per cycle. Thus, the SIU
need to process around 1800 memory requests per cycle to fully
utilize the throughput of the sparse table array. And we choose
2048 as the target of SIU throughput.
A straightforward implementation of SIU is to parallelly accessing the bitmap that stores the sparsity of each entry in a bit.

4.4.2 Our Design. To address the issues of complex routing and
bank conflicts caused by high-throughput random access to SRAM,
we propose a method based on sequential access to SRAM. We
notice that these issues come from the irregular memory access to
the SRAM. So we propose an idea to first sequentially and iteratively
read words from the SRAM, and then match the word with the input
addresses.
Sequential Access. As illustrated in Figure 10(a), Sequential
Access Unit (SAU) perform sequential access to the bitmap in SRAM.
In each cycle, 4 bytes are loaded from SRAM into register A, while
the current access address, which increments by 1 every cycle, is
stored in register B. For an incoming lookup requests, the addresses
are first stored in a buffer. In each cycle, addresses in this buffer are
compared with the address in register B. If some addresses match
the register B, the corresponding bit of data from register A is read
to decide whether these addresses need to be output. If there is no
match, the input addresses remains in the request buffer.
This approach suffers from obvious latency and area overhead issues. Due to the large size of the bitmap, sequentially accessing and
traversing the entire bitmap takes a significant amount of time, resulting in extremely high latency for the matching of some requests.
The high latency in processing requests leads to a large number of
requests accumulating in the buffer, causing substantial overhead
for buffer capacity and associated wiring for address comparison.
Our evaluation shows that, to achieve the target throughput, the
buffer needs to accommodate 1,059,584 memory access requests,
with the total area for buffers and address comparison reaching
418𝑚𝑚 2 , which is unpractical.
Parallel Matching. To mitigate this issue, we increase the number of SAUs and all memory access requests are compared with
them in parallel. These SAUs access multiple SRAM banks in parallel at regular intervals. Thus that the latency for matching is largely
reduced. Since the access to SRAM is sequential, ensuring that the
initial access addresses of different SAUs are not in the same bank
prevents bank conflicts.
However, parallel comparisons with multiple SAUs have led to a
multiplicative increase in the number of comparators, and a highradix crossbar is also require to connect the SAUs with the memory
access requests in the request buffer. Our evaluation shows that to
achieve the throughput target, the total area for the comparison
network is 123𝑚𝑚 2 , which accounts for approximately 52.37% of
the total chip area.

4.5

MLP Units with Dynamic Shared Buffer

Following the aforementioned optimizations, the encoding stage
is accelerated by 7.54×, making MLP units the new bottleneck. To
improve the overall throughput, it is necessary to increase the number of MLP units. We find that the number of MLP units needs to be
increased by at least 4× to match the throughput of the optimized
encoding stage. However, since each MLP unit of Cambricon-R
contains a large local buffer to store the training data of a ray, directly increasing the number of MLP units by 4× would require an
additional total buffer capacity of 144 MB, significantly raising the
cost of the chip. As illustrated in Figure 8, we propose a design with
dynamic shared buffers that reduces the average buffer capacity
required per MLP unit, so that we can largely increase the number
of MLP units to improve performance.
4.5.1 Shared Buffer. Since the minimum unit to compute loss is a
ray, each MLP unit performs MLP training with the granularity of
all points along a single ray. Since the number of sampled points
for each ray in the NSR algorithm varies, Cambricon-R designs the
capacity of the local buffer in each MLP unit based on the maximum
number of effective sampled points. This ensures support for fully
fused on-chip training of the MLP. We observe that the number
of sampled points for most rays is much less than the maximum,
resulting in an average utilization rate of the local buffer being only
20.29%.
Based on this observation, we propose a design scheme where
multiple MLP units share a buffer to enhance buffer utilization. The
capacity of the shared buffer is greater than the maximum capacity
required by a single ray, yet less than the total capacity if each of
these MLP units had their own buffer. This design ensures that

1263

even in extreme cases, the training of the ray with the maximum
number of sampled points can be fully fused on the chip, while
also avoiding the wastage of buffer capacity that occurs with most
smaller rays.
The storage of the shared buffer is divided into two categories
based on the type of data. Weights and the accumulated weight
gradients, which are small in volume, are shared among all MLP
units and stored in the weight buffer. In the forward stage, we
use prefetching and merge memory accesses for the same address.
In the backward stage, gradients computed by the MLP units are
accumulated into the corresponding weight buffer using atomic
operations. The activation data and their gradients for different
rays are independent from each other. Each MLP unit occupy a
larger volume for the activation and gradient data. And the volume
varies for different rays. These data are stored in the activation
buffer.
To simplify the management, the activation buffer is divided
into multiple blocks. Each block is used to store training data for
32 points belonging to the same ray. Additionally, the processing
of each ray is divided into multiple batches, each consisting of 32
points. This prevents conflicts when multiple MLP units access the
shared activation buffer. Each group of MLP units is managed by a
control unit, which contains a group of flag registers to maintain
the states of each block of activation buffer. When processing a new
batch of points, the MLP unit is first assigned a buffer block whose
corresponding state register equals to 0 and changes it into 1. Then,
the MLP unit record the index of this buffer block in a queue, thus
it knows where to access each batch of points. After the finishing
of each ray, the MLP unit change the state registers of the index in
its queue into 0, and then free the queue.
4.5.2 Dynamic Buffer Management. The aforementioned scheme
utilizes the dynamic sharing of the activation buffer among different
MLP units to improve buffer utilization. Furthermore, we propose
dynamic space management in the training of a single ray to reduce
the capacity requirement of each block of activation buffer.
The baseline solution for performing MLP training is to allocate
independent storage space to the activation and its gradient of all
layers. However, each tensor in the MLP network has a different life
period, which is an period from the first write of this data to the last
read of it. We observe that the life period of some tensors begins
after the end of some other tensors. For example, after computing
the weight gradient and input gradient for the 5-th layer during
the backward pass, the input activation of the 5-th layer can be
deleted and the corresponding storage space can be released and
reallocated to the input gradient of the 5-th layer. This inspire us
that the later tensor can use the space released by the former tensor
to save the use of memory space.
Based on this observation, we adopt dynamic buffer management, which dynamically allocates and releases storage space for
different tensor within a block of the activation buffer. Experimental results show that this approach can reduce the size of each block
of activation buffer by 49.42%.

5 Experimental Evaluation
5.1 Methodology
5.1.1 Hardware Implementation. To evaluate Cambricon-SR, we
develop a cycle-accurate simulator to measure runtime and hardware utilization. This simulator also tracks the number of DRAM
access, enabling the calculation of energy consumption associated
with off-chip memory accesses. Same as the baseline hardware
configuration, we employ HBM2 as the off-chip memory, which
offers a bandwidth of 1,555 GB/s. For accurate simulation of DRAM
timing, Ramulator [20] is integrated into our simulator.
We also implement an RTL design of Cambricon-SR using Verilog
to evaluate the area and energy consumption of Cambricon-SR. The
RTL design is then synthesized using the Synopsys Design Compiler,
targeting the TSMC 45nm technology node at a clock frequency of
750 MHz. The energy consumption of off-chip memory accesses
is estimated at 3.9 pJ/bit [38]. Given that the baseline hardwares
operate on a 7nm node, we scale the area and power measurements
of Cambricon-SR to the 7nm node, based on the method described
in [44]. This approach is commonly used in research papers [26, 31].

1264

5.1.2 Datasets & Benchmarks. Eight datasets are involved in our
evaluation, including Ficus, Hotdog, Mic, Fox, Bonsai, Room, Counter,
and Kitchen. Ficus, Hotdog, and Mic are synthetic datasets from
commonly-used NeRF-Synthetic [32]. Fox is a small-scale realworld dataset from Instant-NGP [36]. The other four datasets are
larger-scale real-world datasets from Mip-NeRF-360 datasets [3].
We evaluate Cambricon-SR on three typical NeRF-based NSR
algorithms: Instant-NGP [36], Zip-NeRF [4], and K-Planes [12]. In
our experimental evaluation, the number of entries in each level
of encoding tables and the MLP network configurations are same
across the three algorithms. Instant-NGP and Zip-NeRF employ
hash grid encoding, while K-Planes employs multi-planes encoding.
Runtime and energy results in Section 5.2 are measured when the
training quality reaches a PSNR of 25 following prior works [24].
5.1.3 Baselines. Cambricon-SR is compared against two baseline
hardwares: GPU and an NSR accelerator, Cambricon-R [42]. We
choose NVIDIA A100 as the GPU baseline. For evaluations of
Instant-NGP on the GPU, we execute open-source CUDA codes
obtained from the official Instant-NGP repository [37]. It is specifically optimized in small matrix multiplications with tensor cores.
However, the irregular fine-grained memory accesses during the
encoding stage still leads to low utilization. This code is also the
GPU baseline for many NSR accelerators [21, 24, 42, 55]. Zip-NeRF
and K-Planes are evaluated in the Nerfstudio framework [45]. To
fairly compare with Cambricon-R, we also implement Cambricon-R
in a cycle-accurate simulator according to its paper.

5.2.2 Performance. Figure 14 shows the total training time on 8
datasets and the geometric mean of both our design and baselines.
The results indicate that Cambricon-SR achieves 1259× and 4.12×
speedup on average over GPU and Cambricon-R, respectively. The
performance improvement of Cambricon-SR over Cambricon-R
mainly comes from two aspects. On the one hand, the sparsification
of the encoding table reduces the number of valid table accesses
and invalid table accesses are filtered by SIU. On the other hand,
by sharing buffers among different MLP units, the size of the buffer
is decreased, allowing more compute units to be added.
As shown in Figure 14, the runtime for the first four datasets
is significantly shorter than that of the latter four datasets. The
main reason is that the latter four datasets are larger-scale and
more iterations are needed to reach the same PSNR, as mentioned
in Section 5.1.2. For instance, to achieve a PSNR of 25 in InstantNGP, around 200 training iterations is required in the small-scale
dataset Fox, while around 4,300 training iterations is required in
the large-scale dataset Kitchen.

speedup. This is a worthwhile trade-off.
5.2.4 Off-chip Memory Access. Figure 17 compares the total amount
of off-chip memory accesses of Cambricon-SR and baselines during
the NSR training. Compared with GPU, both Cambricon-SR and
Cambricon-R significantly reduce the off-chip memory accesses because they store most of the intermediate results on-chip and avoid
the off-chip memory access of intermediate results. Cambricon-R
eliminates nearly all off-chip memory accesses by storing the entire encoding table and all intermediate data during the training
process on-chip. Cambricon-SR stores the sparse encoding table
and table gradients on-chip, eliminating off-chip memory accesses
during the forward and backward computation stages. However, in
Cambricon-SR, off-chip access to the dense table is still required
during the update stage of each training iteration. Therefore, more
off-chip memory accesses are required for Cambricon-SR compared
with Cambricon-R.

Related Work

We review the related works on neural scene representation and
neural rendering algorithms and hardware accelerators for neural
scene representation and neural rendering.

ISCA ’25, June 21–25, 2025, Tokyo, Japan

Liu et al.

Neural scene representation and neural rendering algorithms. Neural scene representation and neural rendering are first
proposed by [33] in 2020. [33] proposes the basic idea and process of neural scene representation. However, it introduces a large
amount of computations into the rendering process due to the
large MLP. Many algorithms are proposed to solve this problem.
Instant-NGP [36] introduces the encoding table to learn some of
the representations so that the size of MLPs can be reduced. ZipNeRF [4] combines the anti-aliasing features of Mip-NeRF 360 with
the fast grid training of Instant-NGP, which not only improves the
rendering quality but also effectively speeds up the training.
Sparse NSR Algorithm. Currently, many works have applied
sparsification to NSR algorithms [13, 28, 36, 50]. [28] represents
scenes using a sparse voxel octree format, allowing the rendering
process to skip voxels that do not contain scene information. [13]
represents a scene as a sparse voxel grid with spherical harmonics,
which eliminates the need for neural networks and significantly
improves training and rendering speed. [36] maintains an occupancy grid during training to record the occupancy of each grid
cell, skipping sampled points within empty grid cells. These sparse
algorithms perform sparsification during the sampling stage, skipping sparse sampled points. In contrast, our proposed sparse algorithm further sparsifies the encoding table during the encoding
stage, allowing it to bypass parts of the dense sampled points when
accessing sparse table entries.
Hardware Accelerators for NSR. Recent works have proposed
several accelerators for both NSR modeling [24, 40, 42, 55] and
rendering [11, 14, 16, 21, 22, 35, 39]. [21] proposes restricted hashing
algorithm, which can avoid the irregular off-chip memory access by
partitioning the hash table and loading only a portion of the table
into on-chip memory at a time. [11] introduces a frame reusing
algorithm, which exploits the similarity between adjacent frames
during the rendering process. [24] proposes to split the NSR hash
grid into 2 parts and reduce the grid size and update frequency for
the less sensitive branch. [55] employs a Near Memory Processing
(NMP) architecture to address the memory access bottleneck in
the NSR processing. [42] proposes a ray-based execution flow to
eliminate almost all of the off-chip memory accesses and an NoC
to address the challenges of irregular memory access.

7

Conclusion

In this paper, we propose Cambricon-SR, an algorithm-hardware
co-designed accelerator to improve NSR performance and quality.
We propose a novel NSR algorithm with sparse encoding table, it
achieves more than 80% of sparsity for the encoding table with negligible accuracy loss. To the best of our knowledge, this is the first
NSR training algorithm with sparse encoding tables. Then, to efficiently eliminate the invalid memory access requests to the pruned
entries, we propose the sparse index unit based on sequential SRAM
access to address the challenge of irregularity memory access to the
bitmap. It achieves a throughput increase of 7.54× for the encoding
stage with an additional area overhead of 8.59%. Third, we propose
the dynamic shared buffer for the MLP units to reduce the buffer
usage by 85.3% so that we can increase the number of the MLP
units by 4× with acceptable cost of on-chip buffers. We conduct
evaluations on 8 typical scenes. The results show that, compared

1267

with A100 GPU and Cambricon-R, Cambricon-SR achieves 1259×
and 4.12× speedup, and reduces the energy consumption by 1139×
and 2.98× for each training iteration of NSR, respectively. Thus,
Cambricon-SR largely improves both the performance and quality
compared with the baseline.
